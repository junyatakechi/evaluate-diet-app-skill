# データの出所

何をどのデータから読むか。判断ではなく、この環境での記録の取り決め。記録をどう扱うかの判断は、中核判断の委任表とまだ切り出していない判断の表の判断先にある。

## 何がどこにあるか

| データ | 出所 | 読み方 |
|---|---|---|
| 体重・体組成 | Notionの体重記録DB（collect-renpho-records-app-skill が同期） | 体組成計の導入以降は体脂肪率・除脂肪体重・骨格筋量など17項目。それ以前は体重のみの手入力で、欠測日がある |
| 睡眠の区間（スマートリング） | Notion の Oura 睡眠区間DB（collect-oura-records-app-skill が同期） | 夜の主睡眠の開始・終了。昼寝は読み出しで外す（oura-api-generic-logic-skill の睡眠区間の判断） |
| 睡眠の区間（メモアプリ） | Notion Routine DB の「睡眠時間」の行 | `Executed time` の開始・終了が就寝・起床。対象者の自己申告で、`Status` が `Succeed` の行だけが実行した記録 |
| 歩数 | Notion の Oura 日次サマリーDB（collect-oura-records-app-skill が同期） | 1日1行の `歩数`。その日の値は翌朝に確定する（oura-api-generic-logic-skill のデータが確定する時期の判断） |
| 食事・間食・外食の内容 | Googleカレンダー | Routine DBには食事の内容は入らない |
| 出来事（体調・外出・運動など） | 食事の記録と同じGoogleカレンダーの、括弧が続かない予定 | 評価の図の示唆で、その週に何があったかと、作業・打ち合わせの時間（`作業`・`MTG` などで始まる予定）と遊びの時間（`Youtube`・`ゲーム`・`アニメ`・`VRChat` などで始まる予定）を書くのに使う。判断の材料にはしない |
| 目標体重 | 起動フォルダの `diet-goal-weights.json` | `{"マイルストーン1": 70, "マイルストーン2": 65}` のように、名前と体重（kg）の組を書く。複数あってよい。形は `diet-goal-weights.example.json` |
| 記録の語彙 | このスキルの `conventions/meal-words.json` | 下の「記録の語彙」 |

## 睡眠の記録の出所

起床・就寝時刻の選び方の判断（diet-process-jayt-core-logic-skill の `sleep-time-source.md`）に渡す、この導入先の出所。ウェルネスアプリは使っていない。

| 出所 | 記録 | 性質 |
|---|---|---|
| スマートリング | Oura の睡眠区間 | 客観 |
| メモアプリ | Routine DB の「睡眠時間」 | 主観（自己申告） |

カレンダーの睡眠・起床・就寝準備の予定は、繰り返し予定で過去の分まで書き換わるので、出所にしない。

## カレンダーの食事の記録

食事の記録は、`食事`・`おやつ`・`デザート` のどれかで始まり、すぐ括弧が続く予定。括弧の中は、入手元の印（`内食`・`中食`・`外食`）と品目を `,` で区切って並べ、品目の後ろの `*2`・`*20g` は数量。括弧のあとに、強調・内省の表現と、`at 店名`・`from 店名`・`w/ 同席者` を書く。

```
食事(内食, 鶏むね, もち麦ごはん, 目玉焼き*2)
食事(外食, 焼肉)! at 焼肉店 w/ Aさん
おやつ(プリン)
18:00-21:00 食事会: 自分<>Aさん
```

（架空の例）

括弧が続かない予定（例の4行目）は、食べた記録ではなく出来事なので、食事の記録にしない。カレンダーには食事の内容そのものが入っている。指示者に「何を食べたか」を聞き直す前に、まずここを見る。

## 記録の語彙

食生活の異常検知の判断（diet-process-jayt-core-logic-skill の `meal-pattern.md`）に渡す、カレンダーの記録に書かれる語や印。「この語は間食」という対応付けなので、この導入先の取り決めとして持つ。

**語の正は `conventions/meal-words.json`。** この節は説明で、語を足す・消すときは JSON を直す。キーは材料のキーと同じで、値は語の並び。`at ` のように、後ろの空白まで含めて語にしてよい。

| 材料（JSONのキー） | 語 |
|---|---|
| `間食の表現` | 間食の記録に書かれる表現 |
| `過食の表現` | 過食の記録に書かれる強調表現・内省表現 |
| `外食の表現` | 外食の記録に書かれる表現 |
| `外食を否定する表現` | 外食ではない記録に書かれる表現 |
| `中食の表現` | 中食（買ってきたものを食べる）の記録に書かれる表現 |
| `内食の表現` | 内食（家で作って食べる）の記録に書かれる表現 |

JSONに無いキーは、材料から外す。その項目は、食生活の異常検知が見ない。

## 記録の限界

記録の限界は事実として書く。その限界にどう反応するかは、右の列の判断先にある。

| 記録の限界 | 判断先・渡し方 |
|---|---|
| Routine DB の睡眠時間は自己申告で、15分刻み | 材料の `夜間睡眠` の `出所` を `メモアプリ` で渡す。扱いは diet-process-jayt-core-logic-skill の起床・就寝時刻の選び方の判断（`sleep-time-source.md`） |

## 対象にしないデータ

- セルフモニタリングDB：評価に使わない。
- ほかのカレンダー（ルーティンの繰り返し予定・他人の予定など）。
